# Participate in the StakeReloadXS community

StakeReloadXS Discussions is the public venue for ideas, questions, and constructive feedback. You do not need to be a developer to contribute.

## Choose the right place

| Topic | Where |
| --- | --- |
| New feature or product improvement | [Discussions](https://github.com/StakeReloadXS/StakeReloadXS/discussions) — select the feature-request/ideas category shown in the interface |
| Question, experience, or general feedback | [Discussions](https://github.com/StakeReloadXS/StakeReloadXS/discussions) — select the relevant category |
| Confirmed, reproducible software defect | [Issues](https://github.com/StakeReloadXS/StakeReloadXS/issues) in the component's repository |
| Source changes or documentation fixes | Pull request in the owning repository |
| Security-sensitive information | Private reporting channel; **never** a public issue or discussion |

## Feature request format

Check existing discussions first, to avoid duplicates. Then use the category's existing form/template when one is provided. The following outline helps you prepare your proposal; it does **not** replace the category's established format.

1. **Problem:** What is difficult or missing? Who experiences it?
2. **Proposed experience:** What would you like to happen?
3. **Use case:** When and why would you use it?
4. **Acceptance criteria:** How could a reviewer tell it works?
5. **Constraints or alternatives:** Optional considerations, screenshots, or sketches with sensitive data removed.

One proposal per discussion makes voting and tracking more useful. Upvotes show interest, not a delivery guarantee.

## What happens next

Maintainers may ask clarifying questions, merge duplicates, investigate feasibility, link a discussion to an implementation issue, or defer a proposal. No discussion is an implementation commitment until maintainers identify scope and prioritize it. Legal, security, and external-platform reviews may block some requests.

## Community guidelines

Be specific, respectful, and constructive. Critique ideas and software, not people. Avoid harassment, spam, self-promotion unrelated to the project, and unverified accusations against identifiable people. Never share credentials, session tokens, payment details, account identifiers, or private third-party data. Remove sensitive details from screenshots and logs.

## Developer contributions

For non-trivial changes, discuss the approach before sending code. Keep changes scoped, document tests and limitations, and link a corresponding issue or discussion. Do not expose server secrets or imply that planned licensing, payments, and entitlement flows are approved for implementation.
